Twenty ways to make Versatile feel as finished as it is

Versatile already does the hard parts: focus rings, reduced motion, high contrast, focus traps, a command palette, onboarding, empty states with actions, and a panel grammar applied to fifteen panels. So this study does not recycle the usual list. Every example names what the code does today (with the file), what to build instead, and shows a working demo built on the shipped --vers-* tokens, so it renders in both themes; try the button in the header.

01

Flush saves when the tab closes; show save state in the title

P0quick win
Today

IndexedDB writes are debounced 500 ms per field and progress by 10 s (AGENTS.md → Performance rules, useFlowSave). There is no beforeunload handler anywhere in src/ and nothing sets document.title. Close the tab within half a second of typing and the last sentence is gone, silently; and with six project tabs open, none of them says which is which or which is still saving.

Proposal

Flush every pending debounce on pagehide / visibilitychange: hidden (synchronous put, no prompt: autosave is the promise). Set document.title to ● Chapter 4 — The Long Night — Versatile while a write is pending and drop the dot on commit. Announce nothing; the title is the indicator.

window.addEventListener('pagehide', flushAllTimers) document.addEventListener('visibilitychange', () => { if (document.hidden) flushAllTimers() }) watch(pendingWrites, n => { document.title = (n ? '● ' : '') + chapter + ' — ' + project + ' — Versatile' })
Type, then "close tab" before the save lands
Chapter 4 — The Long Night — Versatile
saved

02

Goal and streak move with the header count

highquick winaudit #14
Today

docs/UX-AUDIT.md #14 (open): the daily goal bar and streak hang off recordProgress(), which runs on the 10 s save debounce, while the header word count updates on the 300 ms wordCountTimer. The two disagree for ten seconds after every burst, and a writer who hits the goal sees the bar lag the number that told them so.

Proposal

Derive todayWords from manuscriptWordCount − startOfDayCount as a computed on the store, so the bar and streak read the same value the header reads. Keep the 10 s persistence; it is only the display that should not wait. Ease the bar width (250 ms) so it reads as growth, not a jump.

03

Find and replace in the manuscript

high1 day
Today

Zero matches for find/replace in src/. Renaming a character after chapter twelve, or fixing a place name the generator spelled two ways, means the browser's find (which cannot replace, and cannot see collapsed chapters) or an export round-trip.

Proposal

A TipTap extension with a Decoration set: ctrl+F opens a bar docked at the top of the editor (find, replace, match case, whole word, "in all chapters"), Enter steps, ctrl+Enter replaces one, Replace all runs as one undoable transaction. Across chapters it walks manuscriptStore and reports "12 in 4 chapters". The story bible gets the same bar for free.

04

Outline scroll-spy and jump-to-scene

highhalf day
Today

The Outline panel lists scenes; the editor shows one chapter. Nothing links the two: no scrollToScene, no jumpTo in src/, and the outline does not know which scene the caret is in. EditorBreadcrumb shows the chapter, not the scene.

Proposal

Each scene heading in the editor gets data-scene-id; an IntersectionObserver marks the outline row whose heading last crossed the top third of the viewport. Clicking a row scrolls the heading to the top with the anim-* duration. The breadcrumb gains the scene. Cost: one observer, one scrollIntoView.

Scroll the editor; click the outline
05

Manuscript typography preferences and typewriter scrolling

mediumhalf day
Today

The editor is fixed: IBM Plex Mono, clamp(16–18px), 1.75 leading, 66ch (style.css .manuscript, DESIGN.md → Manuscript editor). Focus mode exists (16 files) but there is no size, leading or measure setting, and no typewriter scrolling (fontSize appears only in exportService). Writers on a 13" laptop and on a 32" monitor get the same 66ch at the same size.

Proposal

Three settings on the project (size S/M/L, leading, measure 56/66/76ch) written as CSS variables on .manuscript, plus a typewriter toggle that keeps the caret line at 40 % of the viewport. Keep the typeface fixed: that is the signature. Persist per project, expose in the palette as "Typography…".

06

Writing sprint with a session recap

mediumhalf day
Today

A daily goal, a streak, a heatmap and a RecapBanner exist; a timed sprint does not (no sprint/pomodoro in src/). Sprints are the one technique most working novelists use daily, and everything needed (word delta, the banner) is already in projectStore.

Proposal

Palette action "Start a sprint": 15 / 25 / custom minutes. While running, the header goal chip becomes 12:41 · 214 words; the sidebar and tool panels stay, but generation buttons are disabled (a sprint is for typing). At the end, the RecapBanner shows words, pace and the best minute, with "Again". Stored as a writingSession row so the heatmap can show sprint days.

09

Undo on every delete, through the toast action

highquick win
Today

useNotifications.addToast(msg, type, duration, { action }) already supports an action and, when one is present, suppresses auto-dismiss so the user can reach it. Snapshots and database recovery use undo (10 files match); section and scene deletion in ChapterManager go through a confirm dialog instead: a modal for the common case, and no way back after "Delete".

Proposal

Delete immediately, keep the row in memory for 8 s, toast Chapter 4 deleted · Undo. Undo re-inserts at the same index. The confirm dialog stays only for deletes with children (a chapter with scenes) and says how many. This is the pattern Gmail settled on; it removes the modal from the path and adds a safety net.

Delete, then undo
10

The header count reads words · min read · +today

mediumquick win
Today

The header shows a word count; the goal bar shows today's progress separately; reading time appears nowhere in the UI (the only match is a provider file). A writer asks three questions of that number: how long is it, how long does it take to read, and how much did I add today.

Proposal

One chip, three facts: 2,310 words · 9 min read · +240 today, with the delta in --vers-status-success when positive and muted at zero. Reading time is words / 250 rounded up. Hover shows chapter vs manuscript totals. This is the same data as example 02; only the presentation is new.

11

One context-menu primitive for rows and graph nodes

mediumhalf day
Today

Only CharacterBubble.vue handles contextmenu. Section rows expose actions through an expanded row (docs/UX-AUDIT.md #11 fixed their weights); graph nodes have none. Right-click is how people expect to rename, duplicate and delete a thing they can see.

Proposal

A BaseMenu built on BasePopover: items with icon, label, shortcut hint, danger; opened by right-click or a "⋯" trigger, so keyboard users get the same list. Section rows, scene rows, outline rows, network nodes and canvas cards share it. Add to the primitives catalogue with a story.

12

Read aloud for revision

mediumhalf day
Today

No speechSynthesis anywhere. Hearing prose is the oldest revision trick there is; it catches the repeated word, the sentence that runs out of breath, the dialogue nobody would say. The Polish drawer has lenses and annotations but nothing that plays the text back.

Proposal

A Polish lens "Read aloud": Web Speech API, sentence-level highlighting via onboundary, play / pause / rate, starts from the caret or the selection. No model, no network, works offline. The highlight uses the selection colour so it reads as "where we are".

17

Shaped skeletons on every async panel

mediumquick win
Today

Skeleton.vue has six variants (line · text · circle · card · list · panel) and a story, but only 5 files use it; the rest of the panels that wait on IndexedDB or a model (Story Bible lists, Network, Timeline, Evals) show either nothing or a spinner, then snap into layout.

Proposal

Every panel with an async load renders <Skeleton variant="panel"> (header row + three list rows) until its first data, and variant="list" for refreshes that replace a list. The layout is then stable before the data lands, which is the whole point of a skeleton. One line per panel; the component already exists.

18

Resizable docked panel with a remembered width

mediumhalf day
Today

Tool panels dock to the right of the manuscript and are capped at calc(100vw − 32rem) (DESIGN.md → Panel grammar) so the editor never collapses. There is no resize handle in AppShell.vue; Timeline wants 900 px and Consistency wants 380, and both get whatever the cap gives them.

Proposal

A 6 px handle on the panel's left edge: drag between 320 px and the existing cap, double-click to reset, width remembered per panel in localStorage. Keyboard: focus the handle, arrows move by 16 px. The cap stays as the hard limit.

Scene status as a first-class filter

mediumhalf day
Today

Sections carry a status (ChapterManager: status: 'planning', shown via getStatusLabel) and the generator commits a scene it could not verify as review (CommitService, the generation contract in AGENTS.md). The label is on the row; there is no way to see all scenes awaiting review, which is the one list a writer wants after a chapter run.

Proposal

A BaseChip filter row at the top of the Section Manager with counts (Planning · Drafting · Review · Final), rows marked with BaseStatusDot shapes so status is not colour-only, and a palette entry "Scenes to review (3)". After a chapter run, the panel opens on Review.

20

Chapter word targets against actual counts

mediumhalf day
Today

Targets exist as generation input (GenerationSettingsForm, target length) and the manager shows each chapter's count, but the two never meet: nothing shows a chapter at 1,400 of a 2,500 target, and the daily goal is the only progress bar in the app.

Proposal

An optional targetWords on a section; the row shows 1,400 / 2,500 with a 3 px bar in the row's bottom edge; the manuscript total gets a book-level target. Over-length reads muted, not red: length is a plan, not a rule. The generator pre-fills its target from the section when present.
